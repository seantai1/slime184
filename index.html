Slimelight

A Cinematic Path-Traced Slime for the CS184 Final Project Proposal

Summary

We want to extend the CS184 Project 3-2 path tracer with subsurface scattering, wavelength-dependent dispersion, and HDR environment lighting so we can render a translucent slime blob in a small street scene. The main result will be a final render of the blob in that scene, plus an animated version where it deforms on impact. We also plan to show comparison renders so it is clear what each feature adds.

Problem Description

The visual appeal of translucent materials like jelly, ice, soap, and slime comes from several effects happening at once: light scattering through the material, refraction with chromatic dispersion, reflections from the environment, and light patterns on nearby surfaces. Getting that look right is difficult because each of these effects is expensive on its own, and the material only really reads as “slime” when they work together in the same image.

Real-time engines usually approximate these effects. Screen-space refraction misses anything off screen, baked lighting does not respond well to deformation, and many dispersion shaders are built for speed instead of physical accuracy. We were inspired by Asher Zhu’s UE5 slime demo, and we want to see how close we can get to that kind of look with a physically based offline renderer. To do that, we plan to add three main features to our Project 3-2 path tracer:

  • Subsurface scattering for the translucent volume of the blob
  • Wavelength-dependent dispersion for the chromatic fringing through its refractive shell
  • HDR environment-map lighting to ground the blob in a photographic scene

The challenge is that each feature individually adds variance to the Monte Carlo estimator, and combined they require careful sampling strategies (hero-wavelength spectral sampling, environment-map importance sampling, multiple importance sampling) to converge in a reasonable number of samples per pixel. If this works, we should end up with both a clean final render and a side-by-side comparison that shows what each rendering feature contributes.

Goals and Deliverables

Key Deliverables

  1. Random-walk subsurface scattering integrated into our P3-2 path tracer, validated against a reference render (Mitsuba or PBRT) of a translucent unit sphere.
  2. Spectral path tracing with hero-wavelength sampling and a dispersive dielectric BSDF using a Cauchy or Sellmeier IOR model. Compared against constant-IOR glass on a prism test scene.
  3. HDR environment-map lighting with importance sampling, integrated into our existing direct-lighting code path via multiple importance sampling.
  4. Hero render: a slime blob (static mesh) sitting in a small street scene lit by a Polyhaven HDRi, rendered through our extended path tracer.
  5. Ablation grid: the same blob rendered with each feature toggled independently: (a) no SSS, (b) constant-IOR (no dispersion), (c) constant-color environment, and (d) full pipeline, so each contribution is easy to see.
  6. Final writeup webpage, demo video, and presentation slides.

Stretch Goals

  1. Animated falling-blob sequence. Either a mass-spring soft body simulated in our own code (jello-world style), or a Blender Mantaflow FLIP fluid bake exported as per-frame Alembic meshes, so we can render the blob deforming on impact and merging into a puddle.
  2. Caustics on the wet ground via photon mapping or bidirectional path tracing.
  3. Wet-asphalt BSDF, a specular layer over diffuse with view-dependent gloss, so nearby puddles pick up the blob’s color and silhouette.
  4. Hand-modeled or asset-pack alleyway as the hero scene, instead of a generic street.

How we’ll measure quality

  • Visual: the ablation matrix. We should be able to point to each feature and show the image getting visibly closer to a convincing slime look. The hero render should read stylistically as a cinematic, photographic slime shot.
  • Numerical: variance vs. samples-per-pixel curves for the env-map MIS implementation; convergence plots for SSS validation against a reference renderer on the same sphere; spectral correctness checked against analytical thin-prism dispersion.

Questions we plan to answer

  • Can offline path tracing replicate the visual appeal of a real-time game-engine slime in a physically correct way, given enough samples per pixel?
  • How does spectral dispersion interact with subsurface scattering inside the same translucent material, and how many samples does it take to converge?
  • Where does the bulk of variance in the final scene come from, and which sampling improvement (env-map IS, MIS, hero-wavelength, spectral MIS) targets it best?
