Slimelight

A Cinematic Path-Traced Slime in Tokyo — CS184 Final Project Proposal

Summary

We extend the CS184 Project 3-2 path tracer with subsurface scattering, wavelength-dependent dispersion, and HDR environment lighting to render a translucent slime blob in a small Tokyo street scene. Inspired by Asher Zhu’s real-time UE5 demo TokyOSlime, we ask whether the same striking look can be reproduced more physically — and more correctly — through offline path tracing. Our deliverable is a hero render plus an animated sequence of the blob deforming on impact, with ablation comparisons isolating each rendering feature.

Problem Description

The visual appeal of translucent materials — jelly, ice, soap, slime — comes from a tight composition of physical phenomena: light scattering through a translucent volume, refraction with chromatic dispersion, environment reflection, and caustics on nearby surfaces. Asher Zhu’s real-time UE5 prototype TokyOSlime achieves a striking version of this look using Niagara Fluids and a custom screen-space refraction shader that “marches individual rays on the light spectrum.”

Real-time engines necessarily approximate. Screen-space refraction loses anything off-screen, baked lighting cannot react to deformation, and ad-hoc dispersion shaders trade physical correctness for frame budget. Our project asks the natural follow-up: can we reproduce — and ideally surpass — that look using a physically-based offline renderer? Concretely, we extend our Project 3-2 path tracer with three core features that, together, drive the slime aesthetic:

  • Subsurface scattering for the translucent volume of the blob
  • Wavelength-dependent dispersion for the chromatic fringing through its refractive shell
  • HDR environment-map lighting to ground the blob in a photographic scene

The challenge is that each feature individually adds variance to the Monte Carlo estimator, and combined they require careful sampling strategies (hero-wavelength spectral sampling, environment-map importance sampling, multiple importance sampling) to converge in a reasonable number of samples per pixel. The intellectual payoff is a side-by-side study of how each PBR feature contributes to the final image, plus a single hero render that proves we understood how to compose them.

Goals and Deliverables

What we plan to deliver (baseline)

  1. Random-walk subsurface scattering integrated into our P3-2 path tracer, validated against a reference render (Mitsuba or PBRT) of a translucent unit sphere.
  2. Spectral path tracing with hero-wavelength sampling and a dispersive dielectric BSDF using a Cauchy or Sellmeier IOR model. Compared against constant-IOR glass on a prism test scene.
  3. HDR environment-map lighting with importance sampling, integrated into our existing direct-lighting code path via multiple importance sampling.
  4. Hero render: a slime blob (static mesh) sitting in a small street scene lit by a Polyhaven HDRi, rendered through our extended path tracer.
  5. Ablation grid: the same blob rendered with each feature toggled independently — (a) no SSS, (b) constant-IOR (no dispersion), (c) constant-color environment, (d) full pipeline — so each contribution is visually attributable.
  6. Final writeup webpage, demo video, and presentation slides.

What we hope to deliver (reach)

  1. Animated falling-blob sequence. Either a mass-spring soft body simulated in our own code (jello-world style), or a Blender Mantaflow FLIP fluid bake exported as per-frame Alembic meshes for the merge-into-puddle moment in the reference video.
  2. Caustics on the wet ground via photon mapping or bidirectional path tracing.
  3. Wet-asphalt BSDF — a specular layer over diffuse with view-dependent gloss — so the puddle reflects the blob the way it does in the reference.
  4. Hand-modeled or asset-pack Tokyo alleyway as the hero scene, instead of a generic street.

How we’ll measure quality

  • Visual: the ablation matrix — we should be able to point to each feature and show the image getting visibly closer to the reference. The hero render should be stylistically comparable to a frame from TokyOSlime.
  • Numerical: variance vs. samples-per-pixel curves for the env-map MIS implementation; convergence plots for SSS validation against a reference renderer on the same sphere; spectral correctness checked against analytical thin-prism dispersion.

Questions we plan to answer

  • Can offline path tracing replicate the visual appeal of a real-time game-engine slime, given enough samples per pixel?
  • How does spectral dispersion compose with subsurface scattering inside the same translucent material — how many samples does it take to converge?
  • Where does the bulk of variance in the final scene come from, and which sampling improvement (env-map IS, MIS, hero-wavelength, spectral MIS) targets it best?
